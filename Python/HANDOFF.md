## 4. ГЛАВНЫЕ ПРАВИЛА содержания (соблюдать в каждом уроке)

1. **Плотность.** Уроки не поверхностные, каждый честно на 1,5 ч. Мелкие темы объединять (дети не малыши).
2. **Мини-задания ✍️** прямо в `урок.md` после каждой новой команды: короткое закрепление (1–3 мин) с раскрывающейся подсказкой (`<details>`). Пример: «введи имя и возраст и выведи их».
3. **Разбор ошибок.** В каждом уроке показывать, что Python пишет при ошибке и почему; отдельная таблица «🐞 Разбор частых ошибок». Давать ученику намеренно наткнуться (напр. `str+int` → `TypeError`).
4. **f-строки — основной вывод** (введены в Уроке 1). Использовать везде.
5. **Библиотеки — сквозная линия**, почти в каждом модуле новая. Уже пройдены: `random`, `math`, `datetime`, `time` (М1), `pyjokes` + первый `pip install` (М2), `turtle` (М3 — как игра-пылесос, §7.4) + приёмы `time.sleep`/`print(end=)`/`\r`. Впереди: `json`/`wikipedia`/`requests`/`matplotlib`/`qrcode`/`emoji`/`calendar` (М6), `tkinter` (М7).
6. **«Вкусные» проекты, а не сухие задачи.** Каждый урок даёт осязаемый результат, который хочется показать (бот, калькулятор, предсказатель, погода, игра).
7. **Практика: полные понятные задания; подсказки-наводки, не ответы.** Каждое задание в `практика.md` расписать так, чтобы новичок понял, ЧТО сделать и ЧТО получится (конкретные данные, пример вывода — напр. НЕ «Зачёт, если >= 60 и <= 100», а «Спроси у пользователя балл (число). Если он от 60 до 100 включительно — выведи „Зачёт“, иначе „Не сдал“»). Подсказка — только где реально можно застрять (НЕ у каждой), и это наводка на приём/идею, а НЕ готовый код. Не нужна — не пиши. То же в `самоучитель.md`. **Полные решения — в отдельном файле `практика-решения.md`** (для учителя, без построчных пояснений). ⚠️ **В самой `практика.md` НЕ упоминать про файл решений и про то, что готовые ответы существуют** — ученик не должен об этом знать (никаких строк «Учителю: решения — в …»). ⚠️ **Задания и материалы НЕ используют ещё не пройденные темы** (напр. свои функции `def` — только с Модуля 5; словари/множества — соответствующие уроки М4). Готовые функции (`divmod/sum/max/sorted`) вызывать можно. ⚠️ **Turtle-раздел в `практика.md`:** отдельный блок «**Команды каркаса:**» с описанием каждой команды (`clean(i)` — …, `bar(value)` — …) + задания списком **по одному на строку** (НЕ сжатый ряд через `·`), каждое с полным описанием формы/цели.
   - ⭐ **СТРУКТУРА ПРАКТИКИ (правка автора, важно для ВСЕХ уроков; образцы — М4 после переработки).** Практика НЕ должна быть чередой механических дриллов «выведи последний / только чётные / отсортируй». Три уровня по нарастанию **практичности**: **🟢 разминка** (5–6 коротких дриллов на новую команду — закрепить синтаксис, по 2–4 строки) → **🟡 мини-программы** (7–8 задач с **именем и реальным сценарием**, где новая тема связывается с уже пройденным: `input`, циклы, условия, `random`, строки, f-строки; напр. для словарей — «Мини-паспорт города», «Коды ошибок HTTP», «Меню кафе», «Температура по дням», «Инвентарь-счётчик»; для кортежей — «Точка в четверти», «Список учеников», «Победитель матча», «Сколько это минут» через divmod) → **🔴 со звёздочкой** (5–7 творческих: мини-игры, счётчики, фильтры, комбо — «Угадай координату», «Частота букв», «Голосование с победителем»). Референсы автора этого стиля: `D:\Работа\NADIP\Курсы\2 курс\технический\Урок 6. Кортеж\Практика 2` и `...\Урок 10. Словарь\Практическая работа.docx` (блоки «базовые → комбинированные → творческие с random/строками»). ⚠️ Блоки автора «функции» (def) и «файлы» из тех docx НЕ брать до Модулей 5–6. ⚠️ Соблюдать «не опережать» и внутри уровней: срез `[:]`-копия — только с Урока 3 (в У1–У2 копий срезом нет; список правим напрямую/`.copy()`); `sum/max/min` — с Урока 2 (в У1 максимум ищем циклом). Turtle-практикум остаётся отдельным разделом после 🔴. **Решения в `практика-решения.md` — проверять запуском** (интерактивные — с подставным вводом).
8. **Метки 🧩 (проще) / 🎓 (глубже)** в конце частей и в отдельных секциях.
9. **Ссылки между уроками:** в шапке и подвале `урок.md` — ⬅️ предыдущий · индекс модуля · план · следующий ➡️. В `ПЛАН-КУРСА.md` названия готовых уроков — ссылки на папки. (Ссылки на ещё не созданные уроки — это ОК, станут рабочими позже.)
10. **Не опережать программу.** Если для «красивого» решения нужна ещё не пройденная конструкция (`if`, циклы) — **обойти честно и сделать мостик к будущему модулю**. ## 7. ⚠️ Технические тонкости (Windows) — ВАЖНО

1. **НИКОГДА не ставить эмодзи внутри `print()` в эталонном коде `.py`** и в примерах кода, которые ученик набирает. В консоли Windows (cp1251) эмодзи → `UnicodeEncodeError` и **программа падает**. Кириллица в `print` — OK. Эмодзи — только в тексте `.md`, комментариях и HTML. (Это ровно та боль «работает онлайн, падает на ПК», которую просили решать.)
2. **Каждый эталонный `.py` проверять запуском** перед сдачей урока. Проверять под **дефолтной кодировкой** (эмуляция Windows-консоли), а не только UTF-8:
   ```bash
   printf "ввод1\nввод2\n" | python материалы/файл.py 2>err.txt; echo "exit=$?"; grep -i Error err.txt
   ```
   Для чистого вывода в терминале агента можно добавить `PYTHONIOENCODING=utf-8`, но финальную проверку «не падает ли» делать БЕЗ него.
3. **Проверка отсутствия эмодзи в print** (Python-скрипт):
   ```python
   import re,glob
   emoji=re.compile(r'[\U0001F000-\U0001FAFF\u2600-\u27BF\u2B00-\u2BFF]')
   for f in glob.glob("материалы/*.py"):
       for n,l in enumerate(open(f,encoding='utf-8'),1):
           if 'print(' in l and emoji.search(l): print(f,n,l)
   ```
4. **Turtle-практики = ИГРА «Умный пылесос»** (правило автора, важно!). Turtle — **НЕ отдельная тема и НЕ «нарисуй фигуру»**, а игра-песочница: комната-сетка, ребёнок меняет переменную `TASK` (номер задания, 8–16 заданий растущей сложности) и пишет **только алгоритм на циклах**; мусор/клетки закрашиваются. Правила:
   - **Команды и все идентификаторы — ТОЛЬКО английские** (иначе дети привыкнут к рус. именам — плохая практика): `right() left() up() down() clean()`, `go_to(x,y)`, сенсоры `wall_right/wall_left/wall_up/wall_down/wall`, координаты `x, y`, переменная `TASK`. Русские имена команд — ЗАПРЕЩЕНЫ.
   - **Пошаговая АНИМАЦИЯ обязательна:** движок в режиме `turtle.tracer(0, 0)`, а после каждого хода `turtle.update()` + `time.sleep(_STEP_DELAY)`. **НЕ** `turtle.tracer(1, 0)` (нулевая задержка = всё мгновенно, анимации нет — это был баг). `_STEP_DELAY` вверху файла регулирует скорость.
   - **DESKTOP-фикс:** онлайн-версии старого курса используют `t.tracer/t.update/t.delay` на объекте Turtle → на ПК `AttributeError`. Менять на модульные `turtle.tracer/turtle.update/turtle.done()`.
   - **Файл — СТАРТЕР:** блок «ТВОЙ АЛГОРИТМ» пустой, рабочий пример — в комментарии (как в оригинальных каркасах автора «# ТУТ СОЗДАЙ АЛГОРИТМ»). `turtle.done()` в конце держит окно.
   - **Проверка движка — мок-черепашкой** (fake `turtle` модуль + `time.sleep=no-op`), прогнать все задания эталонными решениями, убедиться, что мусор собирается и выезд за стену ловится.
   - Готовые движки Модуля 3 (образцы): `урок-02.../пылесос.py` (12 заданий, движение), `урок-03.../пылесос_список.py` (`go_to` + zip списков), `урок-04.../пылесос_область.py` (вложенные циклы, области), `урок-05.../пылесос_практикум.py` (16 заданий + сенсоры стен, «змейка» `going_right`).
   - **Turtle в М4 — НЕ только «пылесос»** (образцы, все с шапкой-баннером «(N заданий)» + блоком КОМАНДЫ + ОДНИМ примером-комментарием): `урок-02.../диаграмма.py` (`bar(value)`/`mark_line`, столбчатая диаграмма по списку, 12 заданий), `урок-03.../пылесос_срез.py` (`clean(i)`, убрать клетки срезом `cells[СРЕЗ]`, 14), `урок-04.../художник.py` (`move_to`/`line_to`/`dot`, фигура по вершинам-кортежам, 10). Стиль каркаса един: банер-заголовок с числом заданий, блок «КОМАНДЫ» с описанием, ОДИН пример (задание 1) в комментарии, остальное решают дети (НЕ давать готовые решения в файле).
