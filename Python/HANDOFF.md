## 4. ГЛАВНЫЕ ПРАВИЛА содержания (соблюдать в каждом уроке)

1. **Плотность.** Уроки не поверхностные, каждый честно на 1,5 ч. Мелкие темы объединять (дети не малыши).
2. **Мини-задания ✍️** прямо в `урок.md` после каждой новой команды: короткое закрепление (1–3 мин) с раскрывающейся подсказкой (`<details>`). Пример: «введи имя и возраст и выведи их».
3. **Разбор ошибок.** В каждом уроке показывать, что Python пишет при ошибке и почему; отдельная таблица «🐞 Разбор частых ошибок». Давать ученику намеренно наткнуться (напр. `str+int` → `TypeError`).
4. **f-строки — основной вывод** (введены в Уроке 1). Использовать везде.
5. **Библиотеки — сквозная линия**, почти в каждом модуле новая. Уже пройдены: `random`, `math`, `datetime`, `time` (М1), `pyjokes` + первый `pip install` (М2). Впереди: `turtle` (М3), `json`/`wikipedia`/`requests`/`matplotlib`/`qrcode`/`emoji`/`calendar` (М6), `tkinter` (М7).
6. **«Вкусные» проекты, а не сухие задачи.** Каждый урок даёт осязаемый результат, который хочется показать (бот, калькулятор, предсказатель, погода, игра).
7. **Практика с подсказками, но без решений.** И в `практика.md`, и в `самоучитель.md` — только наводки. Полные ответы — кратко в `преподавателю.md` (для учителя).
8. **Метки 🧩 (проще) / 🎓 (глубже)** в конце частей и в отдельных секциях.
9. **Ссылки между уроками:** в шапке и подвале `урок.md` — ⬅️ предыдущий · индекс модуля · план · следующий ➡️. В `ПЛАН-КУРСА.md` названия готовых уроков — ссылки на папки. (Ссылки на ещё не созданные уроки — это ОК, станут рабочими позже.)
10. **Не опережать программу.** Если для «красивого» решения нужна ещё не пройденная конструкция (`if`, циклы) — **обойти честно и сделать мостик к будущему модулю**. Примеры уже применённые: приветствие по времени через `hour // 6` + список (без `if`); таймер обратного отсчёта «руками» (без цикла); «дни до дня рождения» с оговоркой про отрицательное число; проверку диапазона «0–100» в Модуле 2 Урок 2 делали двумя ветками лестницы (а не через `or`, т.к. логика — только в Уроке 3). **Списки вводим мягко** (для `random.choice` и индексации) начиная с М1, полная тема — Модуль 4.
11. **Несколько разных примеров на конструкцию + лайфхаки В ТЕЛЕ урока** (важное правило от автора, память [[lessons-more-examples-integrate-tricks]]). На каждую новую конструкцию — **минимум 2 непохожих примера** (напр. для `and` — с числами «рост И возраст» и со строками «логин И пароль»). Ключевые приёмы/трюки давать **прямо в `урок.md`** (как 💡/🧰-вставки), а не прятать только в `лайфхак.md`. Пример: цепочка сравнений `5 < a < 10` должна быть в самом уроке. `лайфхак.md` — доп. слой, а не единственное место. Один пример часто непонятен — разнообразие даёт разные «зацепки».

### Стиль оформления `урок.md` (единый по всему курсу)
- Заголовок: `# Урок N — «Название»: подзаголовок 🎯`, под ним строка `**Модуль X · Название · Урок N из M | 2 ак.ч. (1,5 часа)**`.
- Блок навигации (⬅️/➡️) и блок ссылок на файлы урока (🔁📌👨‍🏫🖼🆘🧰).
- Секции: «🎮 Что мы сделаем сегодня» → «💡 Главная мысль» → Части 1..N → «🐞 Разбор частых ошибок» → «🎓 Глубже» → «🧩 Для 5–7 классов» → «🏁 Итог» → «🎮 Викторина» → «🔗 Навигация и материалы».
- Callout-эмодзи: **👀** «Что видишь», **⚠️** ошибка/ловушка, **💡** инсайт «как работает», **✍️** мини-задание, **🏆** проект.

## 7. ⚠️ Технические тонкости (Windows) — ВАЖНО

1. **НИКОГДА не ставить эмодзи внутри `print()` в эталонном коде `.py`** и в примерах кода, которые ученик набирает. В консоли Windows (cp1251) эмодзи → `UnicodeEncodeError` и **программа падает**. Кириллица в `print` — OK. Эмодзи — только в тексте `.md`, комментариях и HTML. (Это ровно та боль «работает онлайн, падает на ПК», которую просили решать.)
2. **Каждый эталонный `.py` проверять запуском** перед сдачей урока. Проверять под **дефолтной кодировкой** (эмуляция Windows-консоли), а не только UTF-8:
   ```bash
   printf "ввод1\nввод2\n" | python материалы/файл.py 2>err.txt; echo "exit=$?"; grep -i Error err.txt
   ```
   Для чистого вывода в терминале агента можно добавить `PYTHONIOENCODING=utf-8`, но финальную проверку «не падает ли» делать БЕЗ него.
3. **Проверка отсутствия эмодзи в print** (Python-скрипт):
   ```python
   import re,glob
   emoji=re.compile(r'[\U0001F000-\U0001FAFF\u2600-\u27BF\u2B00-\u2BFF]')
   for f in glob.glob("материалы/*.py"):
       for n,l in enumerate(open(f,encoding='utf-8'),1):
           if 'print(' in l and emoji.search(l): print(f,n,l)
   ```
4. **Turtle-практики** (Модуль 3): брать из старого курса и **чинить под desktop** — добавлять `screen.mainloop()`/`turtle.done()`, использовать `Screen().tracer(...)` вместо онлайн-специфики. Удачные готовые: «Умный пылесос» (16 задач), рисование по осям. Формат — scaffold: даём стартовый код + список команд, ученик пишет алгоритм.
5. Файлы и папки — **на русском** (`урок-02-калькулятор-и-ники`), это норма проекта.

## 9. Рабочий процесс создания урока (чек-лист)

1. Посмотреть тему урока в [ПЛАН-КУРСА.md](ПЛАН-КУРСА.md) (нужный модуль).
2. `mkdir` папку урока + `изображения/` + `материалы/`.
3. Создать **SVG-схемы** (2–4) → проверить валидность XML.
4. Написать **`урок.md`** (с ✍️мини-заданиями и разбором ошибок, f-строки, навигация).
5. Написать **эталонный код** в `материалы/*.py` → **запустить и проверить** (без падений, без эмодзи в print).
6. Синхронизировать примеры кода в `урок.md` с проверенным эталоном.
7. Написать `итого.md`, `практика.md` (15–30 задач), `самоучитель.md` (15–20), `повторение.md`, `лайфхак.md`, `преподавателю.md`, `изображения.md`.
8. Создать `викторина.html` (копия шаблона + свои вопросы).
9. Обновить статусы: `модуль-XX/README.md`, корневой `README.md`, при готовности модуля — этот HANDOFF (§2) и память.
10. Проверка: все внутренние ссылки резолвятся, викторина `<script>` парная и вопросов ~16, SVG валидны, .py запускается.
11. Обновить память проекта (файл `python-course-year2.md`) — прогресс.

> Уроки создавать **по одному** в полном виде. Не пытаться сгенерировать весь модуль разом.
