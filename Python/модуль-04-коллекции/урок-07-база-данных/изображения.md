## 1. `изображения/таблица-список-словарей.svg` 🗃️
**Когда:** Часть 1 (что такое таблица), 5–21 мин. **Ключевая схема урока.**

Таблица героев: шапка с ключами (`"имя"`, `"класс"`, `"hp"`, `"уровень"`), строки `[0]`, `[1]`, `[2]`. Строка `[1]` (Маг) подсвечена, поле `hp=70` — зелёное. Внизу — `heroes[1]["hp"] → 70` и пояснение про два шага доступа.

**Как обсудить:**
- Каждая строка таблицы — это словарь-запись; ключи — «столбцы».
- Достаём поле в два шага: сначала строка по номеру `[1]`, потом поле по ключу `["hp"]`.
- Это и есть устройство простой базы данных.

## 2. `изображения/фильтр-поиск.svg` 🔎
**Когда:** Часть 2 (фильтр), 21–37 мин.

Слева все записи (воины ✓ зелёные, остальные ✗ красные), в центре условие `if hero["класс"]=="воин"`, справа — новый список «воины». Внизу код фильтра.

**Как обсудить:**
- Фильтр записей — та же схема, что фильтр чисел (Урок 2): пустой список → перебор → условие по полю → `append`.
- Проверяем не число, а ПОЛЕ записи.
- Поиск по имени — тот же перебор, но запоминаем найденную запись.

---

## 3. `изображения/сортировка-по-полю.svg` 🏆
**Когда:** Часть 3 (сортировка), 37–51 мин.

Слева пары `(hp, имя)`, стрелка `.sort(reverse=True)`, справа — те же пары по убыванию hp. Внизу код и пояснение: кортеж выносит поле вперёд, поэтому обычная сортировка расставляет записи по полю (без lambda).

**Как обсудить:**
- Список словарей нельзя просто `sort` — Python не знает, по какому полю.
- Приём: собрать пары `(поле, имя)` — кортежи сравниваются по первому элементу.
- Так сортируют по полю, пока не прошли свои функции (Модуль 5).
