# 🧰 Лайфхаки и разбор ошибок · Урок 5 (итоговый)

## ⚡ Быстрые трюки сборки больших программ

- **Импорты — вверху, один раз.** Даже если библиотека нужна в середине — `import` всё равно ставим в начало файла.
- **Строй по шагам.** Написал часть — запусти. Не пиши сразу 40 строк «вслепую»: ошибку в маленьком куске найти легче.
- **Комментарии-заголовки.** Дели программу на блоки: `# 1. Приветствие`, `# 2. Знакомство` — код читается как план.
- **Трюк «выбор без if»:** `список[число // шаг]` выбирает вариант по диапазону. `hour // 6` → часть суток, `score // 10` → уровень и т.п.
- **Эффект «печатает…»:** `time.sleep(0.7)` между репликами делает диалог живым.
- **Понятные имена переменных** в большой программе критичны: `days_lived`, `greeting`, а не `d`, `g`.

## 🐞 Ошибки при сборке и что значат

| Сообщение | Что случилось | Как чинить |
|-----------|---------------|-----------|
| `NameError: name '...'` | использовал переменную/библиотеку раньше, чем создал/импортировал | импорт вверху; переменную создай выше по коду |
| `IndentationError` | лишний или недостающий отступ | все строки одного блока — с одинаковым отступом |
| `TypeError` при `+` | склеил число со строкой | `str(число)` или считай через `int()` |
| `ValueError` при `date(...)` | несуществующая дата | проверь месяц (1–12) и день |
| порядок вывода «вверх ногами» | перепутал шаги | следуй плану: ввод → расчёт → вывод |

> 💡 **Отладка большой программы:** если что-то не так — **добавь `print()` посередине**, чтобы увидеть промежуточные значения (`print("hour =", hour)`). Это лучший способ понять, где «сломалось».

## 🎯 Привычки хорошего кода (закрепляем на будущее)

- Сначала **план**, потом код.
- **Ввод → обработка → вывод** — структура почти любой программы.
- Запускай часто, читай ошибки (последняя строка + номер).
- Давай понятные имена и комментарии-заголовки.
- Эмодзи — в текст и комментарии, **не** в `print`.
