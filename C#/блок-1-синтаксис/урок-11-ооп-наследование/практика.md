# 🏋️ Практика — Урок 11 «ООП: наследование и полиморфизм»

**Блок 1 · Урок 11 | 30 заданий в 3 уровнях по сложности**

> Пиши и **сразу запускай** (F5 / `dotnet run`). У каждой задачи — **«Должно получиться»** и **💡 подсказка**.
> 🟢 базовый · 🟡 средний · 🔴 со звёздочкой. В уроке разбирали банк — в практике берём **другие** сферы (животные, фигуры, транспорт), чтобы приём закрепился шире. Часть задач **повторяет уроки 1–10** (Math, коллекции, циклы).
> 📌 Шпаргалка: наследник `class Dog : Animal { }` · вызвать конструктор родителя `public Dog(string name) : base(name) { }` · разрешить переопределение — в родителе `public virtual void Voice()`, в наследнике `public override void Voice()` · вызвать родительскую версию — `base.Voice()` · полиморфизм — `List<Animal>` с разными наследниками · доступ: `private` (только свой класс), `protected` (свой + наследники), `public` (все). **Имена — `PascalCase`.**
> 💡 Подсказки — **наводки**, а не готовый код.

## 🟢 Уровень 1 — базовый (примени изученное)

**1. Животное и собака.**
Опиши класс `Animal` с полем `Name`. Сделай класс `Dog`, который **наследует** от `Animal`. Создай собаку и выведи её имя (хотя поля `Name` в `Dog` нет — оно достаётся по наследству).
**Должно получиться:**
```
Собаку зовут Рекс
```
> 💡 Наследование записывают через двоеточие: `class Dog : Animal`. После этого у `Dog` уже есть всё, что было у `Animal`.

**2. Общий метод.**
Добавь классу `Animal` метод `Eat`, печатающий «ест». Вызови его у собаки (метод тоже наследуется).
**Должно получиться:**
```
Рекс ест
```
> 💡 Метод, объявленный в родителе, доступен и у наследника — писать его заново не нужно.

**3. Своё умение.**
Добавь классу `Dog` **собственный** метод `Bark` («Гав!»), которого нет у `Animal`. Вызови его.
**Должно получиться:**
```
Гав!
```
> 💡 Наследник может иметь и свои методы, которых нет у родителя. У других наследников `Animal` этого метода не будет.

**4. Конструктор через `base`.**
Дай `Animal` конструктор, принимающий имя. Пусть `Dog` **передаёт имя родителю** через `base`. Создай собаку в одну строку.
**Должно получиться:**
```
Собаку зовут Бобик
```
> 💡 Наследник не задаёт родительские поля сам — он зовёт конструктор родителя: `public Dog(string name) : base(name) { }`.

**5. Фигура и круг.** *(повтор урока 1: Math)*
Опиши класс `Shape` с полем `Color`. Сделай наследника `Circle` с радиусом и методом `Area`. Создай круг, выведи его цвет и площадь.
**Должно получиться (красный круг r=5):**
```
Цвет: красный
Площадь: 78,54
```
> 💡 `Circle : Shape` получает `Color` по наследству, а радиус и `Area` добавляет свои. Площадь — через `Math.PI`.

**6. Транспорт и машина.**
Опиши класс `Vehicle` с полем `Speed`. Сделай наследника `Car`. Создай машину, задай скорость, выведи.
**Должно получиться:**
```
Скорость машины: 120
```
> 💡 `Car : Vehicle` — и поле `Speed` уже доступно у машины.

**7. Родительский метод у наследника.**
У `Animal` есть метод `Sleep` («спит»). Создай `Cat : Animal` и вызови у кошки `Sleep`, ничего не добавляя в `Cat`.
**Должно получиться:**
```
Мурка спит
```
> 💡 Пустой наследник всё равно умеет всё, что умеет родитель.

**8. Два наследника.**
От класса `Animal` сделай **двух** наследников — `Dog` и `Cat`. Создай по одному и выведи их имена.
**Должно получиться:**
```
Рекс
Мурка
```
> 💡 У одного родителя может быть сколько угодно наследников — каждый берёт общее и добавляет своё.

**9. Наследник с новым полем.**
Пусть `Dog` добавит **своё** поле `Breed` (порода), которого нет у `Animal`. Выведи имя (от родителя) и породу (своё).
**Должно получиться:**
```
Рекс, порода: овчарка
```
> 💡 Наследник = поля родителя + свои новые поля.

**10. Цвет у всех фигур.**
Сделай `Shape` с конструктором, задающим цвет, и наследника `Rectangle`, который передаёт цвет через `base` и добавляет ширину/высоту.
**Должно получиться:**
```
Синий прямоугольник, площадь 24
```
> 💡 `Rectangle(string color, int w, int h) : base(color)` — цвет уходит родителю, размеры остаются у наследника.

## 🟡 Уровень 2 — средний (virtual / override / base)

**11. Голос животного (`virtual`/`override`).**
Сделай у `Animal` метод `Voice` **виртуальным** (звук по умолчанию), а у `Dog` **переопредели** его на «Гав!». Вызови у собаки.
**Должно получиться:**
```
Рекс: Гав!
```
> 💡 В родителе метод помечают `virtual` (разрешить менять), в наследнике — `override` (заменить поведение).

**12. Кошка мяукает.**
Добавь `Cat : Animal`, который переопределяет `Voice` на «Мяу!». Проверь, что собака и кошка звучат по-разному.
**Должно получиться:**
```
Рекс: Гав!
Мурка: Мяу!
```
> 💡 Каждый наследник даёт свой `override` — один и тот же вызов `Voice` работает по-разному.

**13. Дополнить, а не заменить (`base.`).**
Пусть у `Dog` метод `Voice` сначала вызывает **родительскую** версию, а потом добавляет своё «Гав!».
**Должно получиться:**
```
(звук животного)
Гав!
```
> 💡 Из переопределённого метода можно позвать оригинал родителя через `base.Voice()`, а потом дописать своё.

**14. Площадь разных фигур.** *(повтор урока 1: Math)*
Сделай `Shape` с виртуальным методом `Area` (по умолчанию 0). Переопредели его в `Circle` и `Rectangle`. Выведи площади обоих.
**Должно получиться:**
```
Круг: 78,54
Прямоугольник: 24
```
> 💡 `Area` в родителе — `virtual` (заглушка), в каждом наследнике — свой `override` с настоящей формулой.

**15. Защищённое поле (`protected`).**
Сделай у `Animal` поле `energy` **защищённым** (`protected`), чтобы его видели наследники, но не посторонний код. Пусть `Dog` в методе `Run` уменьшает энергию.
**Должно получиться:**
```
Энергия после бега: 80
```
> 💡 `protected` — «для своих»: доступно самому классу и его наследникам, но недоступно снаружи (в отличие от `public`).

**16. Визитка через `override`.**
Дай `Animal` виртуальный метод `Info` («Я животное <имя>»), а у `Dog` переопредели на «Я пёс <имя>».
**Должно получиться:**
```
Я пёс Рекс
```
> 💡 Тот же приём `virtual`/`override`, но для текстового представления объекта.

**17. Не все переопределяют.**
Пусть у `Animal` `Voice` виртуальный, `Dog` его переопределяет, а `Fish : Animal` — **нет**. Проверь, что рыба звучит «по умолчанию».
**Должно получиться:**
```
Рекс: Гав!
Немо: (звук животного)
```
> 💡 Если наследник не дал `override`, работает **родительская** версия. Переопределять — по желанию.

**18. Предскажи вывод.**
Не запуская, скажи, что выведет код. Потом проверь.
```csharp
Animal a = new Dog("Рекс");
a.Voice();
```
(где `Voice` в `Animal` — `virtual`, в `Dog` — `override` на «Гав!»)
**Должно получиться:** предсказание и объяснение, **чей `Voice` сработает** — родителя или наследника.
> 💡 Даже если переменная объявлена как `Animal`, объект-то настоящий `Dog`. Сработает та версия, что у **реального** объекта. Это и есть полиморфизм.

**19. Транспорт движется по-разному.**
Сделай `Vehicle` с виртуальным `Move`, а `Car` («едет») и `Plane` («летит») его переопредели.
**Должно получиться:**
```
Машина едет
Самолёт летит
```
> 💡 Общее действие «двигаться» есть у всех, но у каждого своё — классический случай `virtual`/`override`.

**20. Сотрудник и менеджер.** *(повтор урока 1: арифметика)*
Сделай `Employee` с зарплатой и методом `Salary`. Наследник `Manager` пусть переопределяет `Salary`, добавляя премию к базовой (через `base`).
**Должно получиться (база 1000, премия 500):**
```
Зарплата сотрудника: 1000
Зарплата менеджера: 1500
```
> 💡 `Manager.Salary` может взять базовую зарплату у родителя (`base.Salary()`) и прибавить премию.

## 🔴 Уровень 3 — со звёздочкой (полиморфизм, инкапсуляция)

**21. Зоопарк говорит.** *(повтор урока 8: List)*
Собери `List<Animal>` из разных зверей (`Dog`, `Cat`, `Fish`) и в одном цикле вызови `Voice` у каждого — пусть каждый звучит по-своему.
**Должно получиться:**
```
Рекс: Гав!
Мурка: Мяу!
Немо: (звук животного)
```
> 💡 В списке типа родителя `List<Animal>` можно держать любых наследников. Один `foreach` с `Voice` — а звучат все по-разному (полиморфизм, без единого `if`).

**22. Сумма площадей.** *(повтор урока 6: накопитель)*
Собери `List<Shape>` из кругов и прямоугольников и посчитай **общую площадь** всех фигур.
**Должно получиться (круг r=5 и прямоугольник 4×6):**
```
Общая площадь: 102,54
```
> 💡 Перебирай список и складывай `Area()` каждой фигуры — для каждой сработает её собственная формула.

**23. Инкапсуляция счёта.**
Опиши класс `Wallet` с **приватным** балансом. Снаружи баланс нельзя менять напрямую — только через методы `Add` и `Spend` (с проверкой, что хватает денег).
**Должно получиться:**
```
Баланс: 100
Потратить 150? Не хватает
Баланс: 100
```
> 💡 Поле баланса — `private`, чтобы снаружи его не испортили. Все изменения — через публичные методы с проверками. В этом смысл инкапсуляции.

**24. protected против private.**
Покажи разницу: сделай у родителя одно поле `protected`, другое `private`. Убедись, что наследник **видит protected** и **не видит private** (private-поле трогай только через метод родителя).
**Должно получиться:** программа компилируется, только когда наследник обращается к `protected`, а к `private` — через родительский метод.
> 💡 `protected` — «для своих и наследников», `private` — «только этот класс». Попробуй обратиться из наследника к private-полю напрямую — увидишь ошибку компиляции.

**25. Найди и почини ошибку.**
Наследник хочет переопределить метод, но не выходит:
```csharp
class Animal { public void Voice() => Console.WriteLine("звук"); }
class Dog : Animal { public override void Voice() => Console.WriteLine("Гав!"); }
```
**Должно получиться:** `Dog` печатает «Гав!», код компилируется.
> 💡 Переопределить (`override`) можно только то, что родитель **разрешил** менять. Чего не хватает у метода в родителе?

**26. Разные звери — один список.**
Создай `List<Animal>` минимум из 4 разных наследников и выведи у каждого и `Voice`, и `Info`. Убедись, что оба метода работают полиморфно.
**Должно получиться:** каждый зверь и звучит, и представляется по-своему.
> 💡 Тот же приём, что задача 21, но проверяем сразу два переопределённых метода.

**27. Самая большая фигура.** *(повтор урока 6: максимум)*
В `List<Shape>` из разных фигур найди и выведи **наибольшую по площади**.
**Должно получиться:**
```
Самая большая площадь: 78,54
```
> 💡 «Рекордсмен» из урока 6, но сравниваем `Area()` каждой фигуры. Полиморфизм сам подставит нужную формулу.

**28. Парковка транспорта.** *(мини-проект)*
Собери `List<Vehicle>` из машины, самолёта и велосипеда. Пройди по списку и у каждого вызови `Move` — каждый двигается по-своему.
**Должно получиться:** список транспорта, где каждый «поехал/полетел» по-своему.
> 💡 Соедини наследование, `override` и `List<Vehicle>`. Добавить новый транспорт = новый наследник + свой `Move`, остальной код не трогаешь — в этом сила полиморфизма.

**29. Три уровня наследования.**
Сделай цепочку: `Animal` → `Pet : Animal` (добавляет `Owner`) → `Dog : Pet`. Создай собаку и убедись, что у неё есть и имя (от `Animal`), и хозяин (от `Pet`), и лай (свой).
**Должно получиться:**
```
Рекс, хозяин Аня: Гав!
```
> 💡 Наследоваться можно по цепочке: `Dog` получает всё от `Pet`, а `Pet` — всё от `Animal`. Конструкторы передают данные вверх через `base`.

**30. Своя иерархия.**
Придумай и собери **свою** иерархию классов (родитель + 2–3 наследника) с виртуальным методом, который каждый наследник переопределяет по-своему. Идеи:
- 🎮 `Character` → `Warrior`/`Mage`/`Archer` (метод «атака»);
- 🍎 `Food` → `Fruit`/`Drink` (метод «съесть/выпить»);
- 🎵 `Instrument` → `Guitar`/`Drum` (метод «играть»).
Сложи наследников в `List<Родитель>` и вызови метод в цикле.
**Должно получиться:** список объектов, где общий метод у каждого работает по-своему.
> 💡 Реши, что **общего** у всех (в родителе) и что **различается** (переопределяют наследники). Полиморфизм проверь списком родительского типа.
