# 🧰 Лайфхаки и частые ошибки · Урок 11 «ООП: наследование и инкапсуляция»

> Трюки и «грабли» по наследованию. Главное уже показано в уроке — здесь собрано вместе.

---

## 💡 Трюки

1. **Читай двоеточие как «является»:** `SavingsAccount : Account` = «SavingsAccount является Account». Значит, вкладу доступно всё «счётное».
2. **Общее — в родителя, различия — в детей.** Написал поле/метод дважды в похожих классах — вынеси в родителя.
3. **`virtual` + `override` — пара.** Одно без другого не работает. Родитель разрешает (`virtual`), ребёнок меняет (`override`).
4. **`base(...)`** в конструкторе наследника — чтобы родитель заполнил свои поля (не дублируй).
5. **`base.Method()`** — «сделай как родитель, потом добавь своё» (частый приём в `override`).
6. **Список типа родителя** (`List<Account>`) хранит любых наследников — удобно для банка, каталога товаров, отрядов в играх, фигур.
7. **`protected`** — поле «для семьи»: видит класс и его наследники (между `public` и `private`).
8. **Проверка типа:** `if (a is SavingsAccount s) s.AddInterest();` — узнать настоящий тип объекта в списке.

## 🐞 Частые ошибки

| Что видишь | Причина | Лечение |
|-----------|---------|---------|
| `does not contain a constructor that takes 0 arguments` | у родителя конструктор с параметрами, наследник не вызвал `base(...)` | добавь `: base(...)` в конструктор наследника |
| `no suitable method found to override` | забыл `virtual` у родителя | пометь метод родителя `virtual` |
| `hides inherited member ... use 'new'` | забыл `override` | добавь `override` (или это правда новый метод) |
| наследник не видит поле родителя | поле `private` | сделай его `protected` |
| в `List<Родитель>` все ведут себя одинаково | метод не `virtual`/`override` | пара `virtual` + `override` |
| поле меняют снаружи, минуя правила | забыл `private` | прячь данные `private`, наружу — методы |
| «зачем два раза `public`» | по умолчанию всё `private` | публичным членам явно ставь `public` |

---

## 🎯 Три кита ООП (запомни)

- **Инкапсуляция** — прятать данные (`private`) и давать доступ через методы/свойства. *Зачем:* защита от порчи, правила нельзя обойти.
- **Наследование** — брать общее у родителя (`: Base`). *Зачем:* не повторять код.
- **Полиморфизм** — один вызов, разное поведение (`virtual`/`override`, `List<Base>`). *Зачем:* работать с разными объектами одинаково.

---

## ✅ Чек «всё понял»

1. Пишу `class Child : Parent`, вызываю `: base(...)`.
2. Переопределяю методы: `virtual` в родителе, `override` в ребёнке; знаю `base.Method()`.
3. Складываю наследников в `List<Родитель>` — полиморфизм.
4. Прячу данные `private`, открываю `public`-методами.
