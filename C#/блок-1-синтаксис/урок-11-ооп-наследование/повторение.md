## ⌨️ Быстрый разогрев (2 мин)

Набери и запусти — наследник берёт метод у родителя:
```csharp
SavingsAccount s = new SavingsAccount();
s.Owner = "Аня";
s.Deposit(500);
Console.WriteLine($"{s.Owner}: {s.Balance}");

class Account
{
    public string Owner;
    public int Balance;
    public void Deposit(int sum) { Balance += sum; }
}
class SavingsAccount : Account { }
```

- Класс `SavingsAccount` **пустой**, но `Deposit()` работает — он **унаследован** от `Account` (двоеточие `SavingsAccount : Account`). Мы написали `Deposit()` один раз в родителе, а пользуются им все виды счетов. Сегодня научимся ещё и **менять** унаследованное поведение (вклад, карта, зарплатный — по-разному).

## 🌉 Что нового будет сегодня

- **Наследование** `class Child : Parent`, конструктор родителя через `: base(...)`.
- **`virtual`/`override`** — наследник меняет метод; `base.Method()` — версия родителя.
- **Полиморфизм** — `List<Родитель>` из разных наследников.
- **Инкапсуляция** — `private`/`protected`/`public`, прячем данные (баланс).
- Проект — «Банк: счета клиентов» без копипасты.

## 🔮 Что выведет этот код? (повторяем урок 10, на подумать)

Предскажи вывод, **не запуская**:

1.
```csharp
class Cat { public string Name; public Cat(string n) => Name = n; }
Cat c = new Cat("Барсик");
Console.WriteLine(c.Name);
```
2. Подковырка (`static`-счётчик — общий на всех):
```csharp
class Robot { public static int Count; public Robot() => Count++; }
new Robot(); new Robot(); new Robot();
Console.WriteLine(Robot.Count);
```
3. Подковырка (свойство с проверкой в set):
```csharp
class Hero { int hp; public int Hp { get => hp; set => hp = value < 0 ? 0 : value; } }
var h = new Hero();
h.Hp = -5;
Console.WriteLine(h.Hp);
```

<details><summary>✅ Ответы и почему</summary>

1. `Барсик` — конструктор положил переданное имя в поле `Name`.
2. `3` — ❗`static`-поле одно на все объекты: каждый `new Robot()` увеличил общий счётчик.
3. `0` — ❗сеттер проверил значение и заменил отрицательное на 0 (в этом польза свойств).
</details>

## 🐞 Есть ли здесь ошибка? (или всё верно?)

1. `Hero h; h.Name = "Том";`
2. `class Cat { public Cat(string n) { } } Cat c = new Cat();`
3. `class Dog { public string Name; } Dog d = new Dog(); d.Name = "Рекс";`
4. `class R { public static int Count; } Console.WriteLine(R.Count);`
5. `var h = new Hero(); Console.WriteLine(h.Count);` (где `Count` — `static`-поле)

<details><summary>✅ Ответы</summary>

1. ❌ Забыт `new` — объекта нет, обращение к `h.Name` упадёт (NullReference).
2. ❌ Конструктор требует аргумент `n`, а `new Cat()` его не передаёт.
3. ✅ Верно.
4. ✅ Верно — выведет 0 (`static` читают через класс).
5. ❌ `static`-поле читают через **класс** (`Hero.Count`), а не через объект (`h.Count`).
</details>
