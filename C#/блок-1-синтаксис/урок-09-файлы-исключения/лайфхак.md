> Трюки и «грабли» по файлам и исключениям. Главное уже показано в уроке — здесь собрано вместе.

## 💡 Трюки

1. **`File.*` — без открыть/закрыть.** `WriteAllText`/`ReadAllText` делают всё одной строкой (в Python приходилось `open()`/`with`).
2. **`AppendAllText` — для накопления.** `WriteAllText` перезаписывает (стирает старое); чтобы копить записи — только `AppendAllText`.
3. **`\n` в конце строки** — чтобы записи не слипались. Или `File.WriteAllLines(файл, массив)` — сам разложит по строкам.
4. **«Проверь, потом читай»:** `if (File.Exists(файл))` перед чтением — как `ContainsKey` у словаря (Урок 8).
5. **`int.TryParse` вместо `try/catch`** для проверки «число ли ввели» — короче и аккуратнее.
6. **Цикл-переспрашиватель:** `while (!int.TryParse(Console.ReadLine(), out x)) ...` — не примет, пока не введут число.
7. **`ex.Message`** — текст ошибки: `catch (Exception ex) { Console.WriteLine(ex.Message); }`.
8. **`Split(';')`** разбивает строку `"имя;очки"` на массив — удобно хранить в файле «поля через разделитель».
9. **Где файл?** При относительном имени он в `bin\Debug\net10.0`. Нужен на рабочем столе — укажи полный путь.

## 🐞 Частые ошибки

| Что видишь | Причина | Лечение |
|-----------|---------|---------|
| `FileNotFoundException` | читаешь несуществующий файл | `File.Exists` перед чтением |
| данные пропали после записи | `WriteAllText` перезаписал | используй `AppendAllText` |
| всё в одну строку | забыл `\n` | добавь `\n` или `WriteAllLines` |
| `FormatException` | `Convert.ToInt32` от не-числа | `try/catch` или `int.TryParse` |
| `catch` «не сработал» | тип в `catch` не совпал с брошенным | лови нужный тип (или общий `Exception`) |
| `use of unassigned out variable` | взял число из `TryParse` вне ветки `if` | бери его **внутри** ветки, где `TryParse` вернул `true` |
| «файл не создался» | ищешь не в той папке | смотри в `bin\Debug\net10.0` |
| `IOException` при записи | файл открыт в другой программе | закрой файл в редакторе и повтори |

## 🎯 try/catch или TryParse — что выбрать

- **`int.TryParse`** — для обычной **проверки ввода** («а вдруг не число?»). Просто `if/else`, без исключений.
- **`try/catch`** — для более широких опасных операций: работа с файлами, деление, чужой код, где ошибок может быть несколько видов.

> 💡 Часто их совмещают: ввод защищают `TryParse`, а работу с файлом оборачивают в `try/catch`.
