# Лайфхаки к уроку 7 (Блок 2). События и логика 🧰

> Ключевые трюки уже вплетены в `урок.md`. Здесь — дополнительный слой: приёмы, частые «поехало» и как чинить.

---

## 💡 Трюки

**1. Один обработчик — много кнопок.** Не плоди `OnBtn1`, `OnBtn2`, `OnBtn3`. Сделай один `OnClick` и внутри читай `sender`. Меньше кода, меньше ошибок.

**2. Безопасное приведение `sender`.** `if (sender is Button btn)` и проверяет тип, и сразу даёт переменную. Лучше жёсткого `(Button)sender`, который упадёт, если вдруг не кнопка.

**3. Подтверждение перед необратимым.** Удалить, сбросить, выйти, очистить — всегда через `DisplayAlertAsync(..., "Да", "Нет")`. Одна строка спасает данные пользователя.

**4. Ранний выход.** `if (!yes) return;` читается легче, чем оборачивать всё в большой `if (yes) { ... }`. Приём из блока 1.

**5. `IsEnabled` для «пока нельзя».** Кнопка «Отправить» серая, пока форма не заполнена. Включай её в `TextChanged`: `Btn.IsEnabled = !string.IsNullOrWhiteSpace(e.NewTextValue);`.

**6. `IsVisible` для «пока не нужно».** Кнопка «Далее»/«Заново» появляется только после действия. Изначально прячь в XAML: `IsVisible="False"`.

**7. Цепочка присваиваний.** `Btn1.IsEnabled = Btn2.IsEnabled = Btn3.IsEnabled = false;` — включить/выключить сразу несколько.

**8. Заголовок окна — короткий, текст — понятный.** «Удаление» / «Точно удалить запись? Это нельзя отменить.» Человек должен понять, на что соглашается.

## 🩹 Частые «поехало» и лечение

| Симптом | Причина | Лечение |
|---------|---------|---------|
| ошибка «`await` можно только в `async`» | метод не помечен `async` | `private async void OnClick(...)` |
| `DisplayAlert` подчёркнут волной (устарел) | в .NET 10 переименован | используй `DisplayAlertAsync` |
| окно мелькнуло, а `bool` неправильный | забыл `await` перед вопросом | поставь `await`, тогда дождётся ответа |
| «`object` не содержит `Text`» | `sender` имеет тип `object?` | сначала `if (sender is Button btn)` |
| один обработчик реагирует одинаково на все кнопки | не читаешь `sender` | внутри бери `btn.Text`/`btn.BackgroundColor` |
| кнопка не гаснет, а исчезает (или наоборот) | перепутал свойства | серый — `IsEnabled`; спрятать — `IsVisible` |
| после `IsVisible=false` осталась «дырка» | это не про `IsVisible` | `IsVisible=false` убирает и место; «полупрозрачно» — это `Opacity` |
| приложение зависает на окне | несколько окон подряд без `await` | каждому окну — свой `await` |

## 🔎 `async void` — почему именно так

Обычно у методов, которые «ждут», пишут `async Task`. Но **обработчики событий** — исключение: у них `async void` (потому что MAUI вызывает их сам и не ждёт результата). Правило для нашего курса простое: **обработчик с окном → `async void ...(object? sender, EventArgs e)`**. Глубже про `Task`/`async` — в старших темах; сейчас достаточно этого шаблона.
