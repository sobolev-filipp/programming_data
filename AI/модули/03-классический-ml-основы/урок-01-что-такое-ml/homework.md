Ниже работаем с теми же исходными данными, но создаём новое разделение и новую модель. Используй имена с окончанием `_hw`, чтобы не заменить результат совместной работы.

## 🟢 1. Новая проверка на 45 цветках

**Зачем:** самостоятельно пройти путь от разделения до проверки, сохранив тестовые ответы вне обучения.

**Исходные данные:** X и y из Iris. Используй все четыре измерения. Доля проверки — 30%, `random_state=0`, сохранение долей видов. Новая модель — LogisticRegression с лимитом 1000 итераций.

**Что сделать:**

1. Раздели исходные размеры и ответы одним вызовом. Сохрани четыре результата под новыми именами.
2. Выведи формы обеих таблиц размеров и количество ответов каждой части.
3. Создай новый объект модели. Обучи его только на новой учебной части.
4. Получи прогнозы по новой тестовой части, не передавая правильные ответы в predict.
5. Посчитай число совпадений и долю через accuracy_score.
6. Отдельно раздели число совпадений на число проверок и сравни две доли.

💡 **Подсказки:** функция разделения возвращает сначала две части X, затем две части y. Процент в аргументе записывается долей от 0 до 1. Сравнение массивов даёт True/False; их сумма считает верные ответы.

**Что показать:** код и вывод, где видны размеры, число верных из всех проверок и две одинаковые доли.

**Самопроверка:** в test 45 объектов, остальные в train; число строк каждой части совпадает с числом её ответов. В fit нет тестовых переменных. При accuracy 1.0 пустая таблица ошибок в следующем задании будет нормальным результатом.

## 🟢 2. Таблица ошибок и график проверки

**Зачем:** показать не только долю верных, но и конкретные несовпадения и их количество.

**Исходные данные:** измерения тестовых цветков, правильные виды и прогнозы из задания 1. Заново делить или обучать модель не нужно.

**Что сделать:**

1. Создай таблицу тестовых размеров с названиями четырёх признаков.
2. Добавь столбец правильных названий видов и столбец названий, выбранных моделью.
3. Добавь галочки совпадения ответов.
4. Выведи только ошибочные строки.
5. Построй два столбца «Верно» и «Ошибка»: их высоты — количества, а не проценты.
6. Подпиши вертикальную ось и заголовок. Под рисунком запиши фактический итог проверки одной фразой.

💡 **Подсказки:** названия видов лежат в iris.target_names, номера берутся из правильных ответов и прогнозов. Для ошибок нужен обратный к галочкам фильтр. Число ошибок можно получить как все проверки минус совпадения.

**Что показать:** таблицу ошибочных строк, график и предложение вида «Из … цветков верно определено …, ошибок …», подставив свои числа.

**Самопроверка:** высоты складываются в 45. Высота «Ошибка» совпадает с числом строк таблицы ошибок. Если ошибок нет, столбец нулевой и таблица пустая — не нужно намеренно портить прогнозы.

## 🔴 4. Один запрос и пачка из трёх

**Зачем:** проверить, как обученная модель принимает несколько объектов и один объект в одинаковом формате.

**Исходные данные:** обученная модель из задания 1. Три придуманных запроса в сантиметрах:

| Запрос | Длина чашелистика | Ширина чашелистика | Длина лепестка | Ширина лепестка |
|---|---|---|---|---|
| 1 | 5.0 | 3.4 | 1.5 | 0.2 |
| 2 | 6.0 | 2.9 | 4.5 | 1.5 |
| 3 | 6.7 | 3.1 | 5.6 | 2.4 |

Правильные виды этих запросов не заданы. Не назначай прогнозам модели статус правильных ответов.

**Что сделать:**

1. Запиши запросы таблицей из трёх строк в указанном порядке столбцов.
2. Получи три метки одним вызовом predict и переведи их в названия.
3. Передай первый запрос отдельно, сохранив форму таблицы из одной строки.
4. Сравни этот ответ с первым ответом пачки.

💡 **Подсказки:** внешние скобки содержат строки таблицы, внутренние — размеры одного объекта. Для названия вида используй target_names. Один и тот же запрос к одной обученной модели должен дать одинаковый класс независимо от размера пачки.

**Что показать:** три названия, отдельное название и логический результат сравнения.

**Самопроверка:** predict возвращает три ответа для пачки и один для отдельного запроса. Повторное fit не нужно.
