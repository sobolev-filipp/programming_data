# Урок 4.5. Feature Engineering — резюме

---

## Глоссарий новых терминов

| Термин | Что это |
|--------|---------|
| **Feature engineering** | Создание новых признаков из имеющихся данных |
| **Кодирование (encoding)** | Превращение категорий в числа |
| **Label encoding** | Категория → число (для **порядковых**) |
| **One-hot encoding** | Столбец-флаг на каждую категорию (для **непорядковых**) |
| **Бины (binning)** | Число → группа-диапазон (`pd.cut`) |
| **Доменное знание** | Понимание задачи, подсказывающее признаки |
| **Утечка (leakage)** | Признак «подсмотрел» в тест |

---

## Главные мысли

1. **Хорошие признаки часто важнее модели.** «Мусор на входе → мусор на выходе».
2. Feature engineering — это **80% работы** дата-сайентиста.
3. Лучшие признаки рождаются из **понимания задачи** (домена), а не из формул.
4. Простые приёмы дают много: комбинации, флаги, извлечение из текста/дат, бины.
5. Статистики для признаков (медиана, среднее) считать **только на train** — иначе утечка.
6. Простые комбинации (`a + b`) утечки **не** дают; статистики по данным — дают.

---

## Приёмы feature engineering

| Приём | Код | Пример |
|-------|-----|--------|
| Комбинация | `df['a'] + df['b']` | `FamilySize` |
| Отношение | `df['a'] / df['b']` | `FarePerPerson` |
| Флаг | `(df['x'] > 0).astype(int)` | `IsAlone` |
| Из текста | `df['Name'].str.extract(r' ([A-Za-z]+)\.')` | `Title` |
| Из даты | `df['d'].dt.dayofweek` | `is_weekend` |
| Бины | `pd.cut(df['Age'], bins=[...])` | `AgeGroup` |
| One-hot | `pd.get_dummies(df, columns=[...])` | `Title_Mr` |

---

## Кодирование категорий

| Тип категории | Способ | Пример |
|---------------|--------|--------|
| Есть порядок (низкий<средний<высокий) | label encoding | `.map({...})` |
| Нет порядка (титул, город, цвет) | **one-hot** | `pd.get_dummies` |

> Для непорядковых — **всегда one-hot**, иначе модель выдумает ложный порядок.

---

## Как проверять признак

```python
# 1. Осмысленность — связь с целью
df.groupby('new_feature')['target'].mean()

# 2. Польза — рост точности (модель не менять!)
cross_val_score(model, X_with_feature, y, cv=5).mean()

# 3. Важность — что ценит модель
model.feature_importances_
```

## Главные ошибки

| Ошибка | Что не так | Как исправить |
|--------|-----------|---------------|
| Медиана по всем данным | Утечка в тест | Считать на train |
| Label encoding для непорядковых | Ложный порядок | One-hot |
| Слишком много признаков | Переобучение | Знать меру |
| Не проверяют осмысленность | Мусорные признаки | `groupby` по target |

## К следующему уроку

**Урок 4.6. Pipeline в sklearn.** Будем:
- Собирать **всю обработку** (признаки → кодирование → стандартизация → модель) в одну «трубу».
- Узнаем `ColumnTransformer` — разная обработка числовых и категориальных столбцов.
- Поймём, почему Pipeline **защищает от утечек** и упрощает код.

> Сегодня мы создавали признаки «вручную», в функциях. Это работает, но легко запутаться и случайно допустить утечку. **Pipeline** связывает все шаги в одну надёжную цепочку — и код чище, и ошибок меньше. Это финальный «инженерный» навык Модуля 4.
