## Задание 1. Рисуем 30-мерные данные (18 минут)

### Что мы хотим сделать

Взять данные с **30 признаками** и сжать их до **2**, чтобы нарисовать на обычном графике.

**Что мы сделаем:**
1. Загрузим breast cancer.
2. Стандартизуем 30 признаков.
3. Сожмём их до 2 через PCA.
4. Нарисуем — и увидим, разделяются ли классы.

### 1.1. Загрузка данных

```python
data = load_breast_cancer()
X = data.data            # 30 признаков
y = data.target          # 0 = злокачественная, 1 = доброкачественная

print("Форма X:", X.shape)              # (569, 30) — 569 опухолей, 30 признаков!
print("Признаки:", data.feature_names[:5], "...")
```

**Что мы видим:** 569 опухолей, у каждой **30 характеристик** (радиус, текстура, периметр, площадь, гладкость...). На плоскости такое **не нарисовать** — 30 осей не существует.

### 1.2. Стандартизация (обязательно для PCA!)

```python
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)
```

**Зачем:** признаки в разных шкалах (площадь — сотни, гладкость — доли). Без стандартизации PCA «увёл» бы главную компоненту к признакам с большими числами. *(Правило из теории — PCA в «клубе стандартизации».)*

### 1.3. Сжимаем 30 признаков в 2

```python
pca = PCA(n_components=2)
X_pca = pca.fit_transform(X_scaled)

print("Было признаков:", X.shape[1])      # 30
print("Стало:", X_pca.shape[1])           # 2
print("Сохранили информации:", f"{sum(pca.explained_variance_ratio_)*100:.0f}%")  # ~63%
```

#### Что произошло

- PCA нашёл **2 главных направления** (компоненты) в 30-мерных данных.
- **Спроецировал** каждую опухоль на эти 2 оси — получил 2 новые координаты вместо 30.
- `explained_variance_ratio_` говорит: эти 2 компоненты сохранили **~63%** всей информации.

> **30 → 2, и при этом 63% информации на месте.** Остальные 28 признаков «упакованы» в эти 2 суперпризнака.

### 1.4. ⭐ Рисуем то, что нельзя было нарисовать

```python
plt.figure(figsize=(9, 7))
scatter = plt.scatter(X_pca[:, 0], X_pca[:, 1], c=y, cmap='coolwarm', alpha=0.6)
plt.xlabel("Главная компонента 1")
plt.ylabel("Главная компонента 2")
plt.title("Breast cancer: 30 признаков → 2 (PCA)")
plt.colorbar(scatter, label="0=злокач., 1=доброкач.")
plt.show()
```

**Что увидим:** облако точек на плоскости, где **два класса заметно разделены** — злокачественные опухоли в одной зоне, доброкачественные в другой (с небольшим перекрытием на границе).

> **Это почти чудо:** мы **увидели** 30-мерные данные на плоском графике. И сразу понятно — классы **разделимы** (значит, классификатор сработает хорошо). PCA дал нам «карту» данных, которую раньше было невозможно нарисовать.

#### Важная оговорка

> PCA **не знал** про классы (`y`) — он сжимал только признаки `X` (это обучение **без учителя**). То, что классы разделились — приятный **бонус**: значит, в данных и правда есть структура, отличающая опухоли. Цвет мы добавили **сами** уже потом, для наглядности.

### Итог Задания 1

**Что мы сделали:**
1. Взяли 30-мерные данные.
2. Сжали их до 2 через PCA (сохранив 63% информации).
3. **Нарисовали** — увидели, что классы разделяются.

## Задание 2. Сколько компонент оставить (12 минут)

### Что мы хотим сделать

Мы взяли 2 компоненты «на глаз». А сколько нужно, чтобы сохранить, скажем, **95%** информации? Разберёмся через explained variance.

### 2.1. Смотрим вклад каждой компоненты

```python
# PCA со ВСЕМИ компонентами
pca_full = PCA().fit(X_scaled)

print("Доля каждой компоненты:")
print(np.round(pca_full.explained_variance_ratio_[:10], 3))
# [0.443 0.19  0.094 0.066 0.055 ...]
```

**Что видим:** первая компонента — **44%** информации, вторая — **19%**, третья — **9%**... Дальше всё меньше. Первые несколько компонент несут **основную** информацию, остальные — «крохи».

### 2.2. Накопленная доля — главный график

```python
cumsum = np.cumsum(pca_full.explained_variance_ratio_)

plt.figure(figsize=(9, 5))
plt.plot(range(1, 31), cumsum, 'o-')
plt.axhline(y=0.95, color='red', linestyle='--', label='95%')
plt.xlabel("Число компонент")
plt.ylabel("Накопленная доля информации")
plt.title("Сколько компонент нужно?")
plt.legend()
plt.grid()
plt.show()

# Сколько компонент для 95%?
n_95 = np.argmax(cumsum >= 0.95) + 1
print(f"Для 95% информации нужно компонент: {n_95}")   # ~10
```

#### Что мы делаем по шагам

- `np.cumsum(...)` — **накапливает** доли: 0.44, потом 0.44+0.19=0.63, потом 0.72...
- Рисуем кривую — она **растёт и выходит на плато**.
- Красная линия — порог 95%. Смотрим, на какой компоненте кривая её пересекает.
- `np.argmax(cumsum >= 0.95)` — находит первую компоненту, где накоплено ≥95%.

**Что увидим:** для **95%** информации хватает **~10 компонент** (вместо 30). То есть **треть** признаков несёт почти всё!

> Это как **метод локтя** у K-Means: смотрим на кривую и выбираем, где «достаточно». Для рисунка берём 2–3, для сохранения 95% — около 10.

### Итог Задания 2

**Что мы поняли:**
1. Первые компоненты несут **больше всего** информации.
2. График накопленной доли показывает, **сколько** компонент нужно.
3. Для breast cancer 10 компонент (из 30) дают 95% — можно сжать втрое.

## Задание 3. PCA ускоряет модель (8 минут)

### Что мы хотим показать

PCA нужен не только для рисунков. Сжав признаки, можно **ускорить** обучение модели — иногда без потери точности.

### 3.1. Сравним: модель на 30 признаках vs на сжатых

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
import time

# Вариант А: все 30 признаков
start = time.time()
score_full = cross_val_score(LogisticRegression(max_iter=5000), X_scaled, y, cv=5).mean()
time_full = time.time() - start

# Вариант Б: сжать до 10 компонент, потом модель
X_pca10 = PCA(n_components=10).fit_transform(X_scaled)
start = time.time()
score_pca = cross_val_score(LogisticRegression(max_iter=5000), X_pca10, y, cv=5).mean()
time_pca = time.time() - start

print(f"30 признаков:  точность={score_full:.3f}, время={time_full:.3f}с")
print(f"10 компонент:  точность={score_pca:.3f}, время={time_pca:.3f}с")
```

**Что увидим (примерно):**
```
30 признаков:  точность=0.974, время=0.45с
10 компонент:  точность=0.972, время=0.18с
```

#### Что это значит

- Точность **почти та же** (0.974 → 0.972) — мы сохранили 95% информации, потеряли чуть-чуть.
- Время **меньше** — модель работает с 10 признаками вместо 30.

> На маленьком датасете выигрыш во времени скромный, но на **больших** данных (тысячи признаков) PCA ускоряет модели **в разы**. И часто **убирает шум**, что даже повышает точность.

### 3.2. Когда PCA помогает, а когда нет

| Ситуация | PCA полезен? |
|----------|--------------|
| Много признаков (десятки–тысячи) | **Да** — ускорит, уберёт шум |
| Нужно **нарисовать** данные | **Да** — сжать до 2–3 |
| Мало признаков (2–5) | Не нужен — и так всё видно |
| Важна **интерпретируемость** признаков | Осторожно — компоненты это смеси, их трудно назвать |

### Итог Задания 3

**Что мы поняли:**
1. PCA **ускоряет** модели (меньше признаков).
2. При сохранении 95% точность почти не страдает.
3. На больших данных выигрыш гораздо заметнее.
