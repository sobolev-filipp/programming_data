## Задание 1. Разведка: где и когда опаздывают рейсы (EDA)

### 1.1. Загрузка и цель

```python
URL = "https://raw.githubusercontent.com/vega/vega-datasets/main/data/flights-20k.json"
df = pd.read_json(URL)

print(df.shape)         # (20000, 5)
print(df.head(3))

# Создаём ЦЕЛЬ: задержан ли рейс (>15 минут — отраслевой стандарт)
df['delayed'] = (df['delay'] > 15).astype(int)

print("Доля задержанных:", df['delayed'].mean().round(3))   # 0.217
```

**Что мы видим:** 20 000 рейсов, и **21.7%** задержаны. Запомни это число — оно ключевое (дисбаланс!).

## Задание 2. Признаки из даты и проблема 220 аэропортов

### 2.1. Признаки из даты (feature engineering, Урок 4.5)

```python
df['hour'] = df['date'].dt.hour              # час вылета (уже сделали)
df['dayofweek'] = df['date'].dt.dayofweek    # день недели (0=пн, 6=вс)
df['month'] = df['date'].dt.month            # месяц
df['is_weekend'] = (df['dayofweek'] >= 5).astype(int)   # выходной?
```

**Что произошло:** из одной колонки `date` мы достали **4 признака**. Голая дата модели бесполезна, а час/день/выходной — очень полезны (мы это видели на графике!).

### 2.2. Проблема: аэропортов слишком много

```python
print("Уникальных аэропортов вылета:", df['origin'].nunique())     # 220!
```

**В чём беда:** если сделать one-hot для **220** аэропортов — получим **220 новых колонок**! Это много, медленно и ведёт к переобучению (вспомни «проклятие размерности», Урок 4.3).

**Решение — топ-N + Other:** оставим **20 самых загруженных** аэропортов, остальные объединим в `'Other'`.

```python
# Топ-20 аэропортов вылета и прилёта
top_origin = df['origin'].value_counts().head(20).index
top_dest = df['destination'].value_counts().head(20).index

# Остальные → 'Other'
df['origin_top'] = df['origin'].where(df['origin'].isin(top_origin), 'Other')
df['dest_top'] = df['destination'].where(df['destination'].isin(top_dest), 'Other')

print("Стало категорий origin:", df['origin_top'].nunique())   # 21 (20 + Other)
```

#### Что делает `.where(...)`

`df['origin'].where(условие, 'Other')` — оставляет значение, если условие `True`, иначе ставит `'Other'`. Так 220 аэропортов превращаются в 21 категорию: 20 главных + «все прочие». Намного удобнее для one-hot.

> Это **реальный приём** дата-сайентиста: с категориями высокой «кардинальности» (много значений) берут топ-N, остальное группируют. Запомни — пригодится.

## Задание 3. Pipeline и бейзлайн — ловушка accuracy

### 3.1. Собираем Pipeline (Урок 4.6)

```python
# Какие столбцы числовые, какие категориальные
num_features = ['distance', 'hour', 'dayofweek', 'month', 'is_weekend']
cat_features = ['origin_top', 'dest_top']

preprocessor = ColumnTransformer([
    ('num', StandardScaler(), num_features),
    ('cat', OneHotEncoder(handle_unknown='ignore'), cat_features)
])

# Признаки X и цель y. ВАЖНО: 'delay' НЕ берём — это ответ!
X = df[num_features + cat_features]
y = df['delayed']
```

> ⚠️ **Критично:** мы **не включаем** `delay` в признаки. `delayed` сделана из `delay` — если оставить `delay`, модель просто «подсмотрит» ответ (100% точность, но бесполезно). Это была бы грубая **утечка**.

### 3.2. Бейзлайн: логистическая регрессия

```python
logreg_pipe = Pipeline([
    ('pre', preprocessor),
    ('clf', LogisticRegression(max_iter=1000))
])

# Честная оценка по кросс-валидации
acc = cross_val_score(logreg_pipe, X, y, cv=5).mean()
preds = cross_val_predict(logreg_pipe, X, y, cv=5)

print(f"Accuracy:  {acc:.3f}")                          # ~0.782
print(f"Precision: {precision_score(y, preds):.3f}")    # ~0.40
print(f"Recall:    {recall_score(y, preds):.3f}")       # ~0.004 (!!)
print(f"F1:        {f1_score(y, preds):.3f}")           # ~0.008
```

### 3.3. ⚠️ ЛОВУШКА: смотри на recall!

Сравним с «глупой» моделью, которая **всем** говорит «не задержится»:

```python
print("Глупая модель (всем 'не задержится'):")
print(f"  Accuracy: {(y == 0).mean():.3f}")     # 0.783 — ВЫШЕ нашей!
print(f"  Recall:   0.000")                      # ничего не нашла
```

#### Что произошло — главный урок проекта

| Модель | Accuracy | Recall задержек |
|--------|----------|-----------------|
| «Глупая» (всем «не задержится») | **0.783** | **0.000** |
| Наш LogReg | 0.782 | **0.004** |

**Наша «умная» модель почти не лучше глупой!** Accuracy 78% выглядит прилично, но **recall ≈ 0** — модель почти **никогда** не предсказывает задержку, прячется в большинство. Для аэропорта она **бесполезна** — не предупредит почти никого.

> **Вот она, ловушка дисбаланса (Урок 3.4) вживую!** Accuracy 0.78 **обманывает**. Реальное качество показывает **recall** — и он у бейзлайна почти ноль. **Наша задача в самостоятельной части — поднять recall**, чтобы модель реально находила задержки.
