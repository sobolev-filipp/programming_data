## Задание 1. Строим спам-фильтр (18 минут)

### Что мы хотим сделать

Загрузить сообщения, превратить их в числа и обучить модель отличать спам от обычных.

### Что мы сделаем (шаги словами)

1. Загрузим датасет SMS (спам/ham).
2. Разделим на train/test.
3. Превратим текст в TF-IDF (**словарь учим на train!**).
4. Обучим логистическую регрессию.

### 1.1. Загружаем датасет

```python
url = "https://raw.githubusercontent.com/justmarkham/pycon-2016-tutorial/master/data/sms.tsv"
df = pd.read_csv(url, sep='\t', header=None, names=['label', 'message'])

print("Размер:", df.shape)
print(df['label'].value_counts())
df.head()
```

**Что увидим:**
```
Размер: (5572, 2)
ham     4825
spam     747
```

> **Что это значит:** **5572** сообщения. Из них **4825 обычных (ham)** и **747 спама** — спама всего ~13%. Данные **несбалансированы** (ham сильно больше). Запомни это — пригодится при оценке.

### 1.2. Готовим метку и делим на train/test

```python
# Превращаем метку в число: spam=1, ham=0
y = (df['label'] == 'spam').astype(int)
X = df['message']

# Делим: 75% на обучение, 25% на тест (stratify — сохранить долю спама в обеих частях)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y)

print("Train:", len(X_train), " Test:", len(X_test))
```

**Что увидим:**
```
Train: 4179  Test: 1393
```

> **`stratify=y`** следит, чтобы доля спама (~13%) была **одинаковой** в train и test. Без этого случайно мог бы получиться перекос.

### 1.3. Текст → TF-IDF (главное правило!)

```python
tfidf = TfidfVectorizer()

X_train_vec = tfidf.fit_transform(X_train)   # УЧИМ словарь на train + преобразуем
X_test_vec  = tfidf.transform(X_test)        # тест ТОЛЬКО преобразуем (тем же словарём)

print("Размер словаря:", len(tfidf.get_feature_names_out()))
print("Форма матрицы train:", X_train_vec.shape)
```

**Что произошло по шагам:**
- `fit_transform(X_train)` — векторизатор **выучил словарь** по обучающим сообщениям и превратил их в числа.
- `transform(X_test)` — тест превращён в числа **тем же** словарём (новые слова игнорируются).

**Что увидим:**
```
Размер словаря: 7387
Форма матрицы train: (4179, 7387)
```

> ⚠️ **Самое важное место урока:** на train — `fit_transform`, на test — **только** `transform`. Словарь учим **один раз, на обучающих** данных. Если выучить его на тесте — это «подсматривание» (утечка данных), оценка станет нечестной. (Подробнее — [theory.md, раздел 3](theory.md#3-критическая-деталь-учим-словарь-только-на-train).)
>
> Матрица train — **4179 × 7387**: 4179 сообщений, каждое — вектор из 7387 чисел (по слову словаря). Текст стал числами!

### 1.4. Обучаем классификатор

```python
model = LogisticRegression(max_iter=1000)
model.fit(X_train_vec, y_train)        # тот же fit, что в Модуле 3.4!

print("Модель обучена!")
```

> **Узнаёшь?** Это **логистическая регрессия** из урока 3.4 — `model.fit(X, y)`. Код абсолютно тот же, что в Модуле 3. Поменялось только то, что `X` теперь получен из текста через TF-IDF. Вот в чём сила «текст → числа»: дальше работает **всё** ML, что мы знаем.

1. Загрузили 5572 сообщения (несбалансированные: 87% ham).
2. Разделили на train/test, превратили в TF-IDF (**словарь — на train!**).
3. Обучили логистическую регрессию — кодом из Модуля 3.4.

## Задание 2. Честная оценка и свои сообщения (14 минут)

### Что мы хотим сделать

Оценить фильтр **правильными** метриками (не только accuracy!) и проверить на своих сообщениях.

### 2.1. Точность — и ловушка

```python
pred = model.predict(X_test_vec)
print(f"Accuracy: {accuracy_score(y_test, pred):.4f}")
```

**Что увидим:**
```
Accuracy: 0.9720
```

> **97% — звучит отлично!** Но... вспомни: в данных **87% ham**. Значит, «глупый» фильтр, считающий **всё** обычным, дал бы уже 87%. Так насколько хорош наш фильтр на самом деле? Смотрим дальше.

### 2.2. Сравнение с «ленивым» фильтром

```python
# "Ленивый" фильтр: всё считает ham (0). Его точность:
lazy_accuracy = (y_test == 0).mean()
print(f"Точность 'ничегонеделания' (всё ham): {lazy_accuracy:.4f}")
```

**Что увидим:**
```
Точность 'ничегонеделания' (всё ham): 0.8658
```

> 😮 **Вот она, ловушка!** Фильтр, который **ничего не делает**, уже даёт **87%** точности — и при этом не ловит **ни одного** спама. Значит, accuracy 97% звучит красиво, но сама по себе мало о чём говорит. Нужны метрики, которые смотрят на **спам**.

### 2.3. Правильные метрики: precision и recall

```python
print(f"Precision: {precision_score(y_test, pred):.4f}")
print(f"Recall:    {recall_score(y_test, pred):.4f}")
```

**Что увидим:**
```
Precision: 1.0000
Recall:    0.7914
```

#### Что это значит

> - **Precision = 1.00** — из всех писем, что фильтр пометил спамом, **100% действительно спам**. Ни одного нормального письма он не обвинил зря! Для спам-фильтра это **отлично** — мы не теряем важные письма.
> - **Recall = 0.79** — из всего спама фильтр поймал **79%**. Значит, ~21% спама **просочилось** в почту.
>
> Картина честная: фильтр **осторожный** — никогда не трогает нормальные письма (precision 1.0), но за это пропускает часть спама (recall 0.79). Для почты это **правильный** компромисс: лучше увидеть немного спама, чем потерять письмо от друга.

### 2.4. Матрица ошибок

```python
cm = confusion_matrix(y_test, pred)
print("Матрица ошибок (строки=истина, столбцы=предсказание):")
print("           pred_ham  pred_spam")
print(f"true_ham   {cm[0,0]:8d}  {cm[0,1]:8d}")
print(f"true_spam  {cm[1,0]:8d}  {cm[1,1]:8d}")
```

**Что увидим:**
```
Матрица ошибок (строки=истина, столбцы=предсказание):
           pred_ham  pred_spam
true_ham       1206         0
true_spam        39       148
```

> **Читаем матрицу:**
> - `true_ham → pred_spam` = **0** — **ноль ложных тревог**! Ни одно нормальное письмо не улетело в спам. (Поэтому precision = 1.0.)
> - `true_spam → pred_ham` = **39** — 39 спам-сообщений просочились (поэтому recall < 1).
> - По диагонали — верные: 1206 ham и 148 spam распознаны правильно.
>
> Это идеальная иллюстрация: «97% точности» прятала и **0 потерянных писем** (отлично), и **39 пропущенных спамов** (есть куда расти). Только матрица показывает **всю** правду.

### 2.5. Проверяем на своих сообщениях

```python
my_messages = [
    "Hey, are we still meeting for lunch tomorrow?",
    "WINNER!! You have won a FREE prize. Call now to claim 09061701461!",
    "Can you send me the homework please",
]
my_vec = tfidf.transform(my_messages)          # ТОЛЬКО transform (тот же словарь!)
preds = model.predict(my_vec)

for msg, p in zip(my_messages, preds):
    print(f"[{'СПАМ' if p == 1 else 'ham '}] {msg}")
```

**Что увидим:**
```
[ham ] Hey, are we still meeting for lunch tomorrow?
[СПАМ] WINNER!! You have won a FREE prize. Call now to claim 09061701461!
[ham ] Can you send me the homework please
```

> 🎉 **Работает!** Фильтр уверенно поймал спам («WINNER», «FREE prize», «Call now») и пропустил нормальные сообщения. Обрати внимание: для своих сообщений тоже **только `transform`** — словарь не переучиваем.
>
> 📌 Датасет английский, поэтому проверяем английскими фразами. Для русского спам-фильтра нужен русский датасет — но **код и метод будут точно такими же**.

3. **Матрица ошибок** показала: 0 ложных тревог, 39 пропущенных спамов.
