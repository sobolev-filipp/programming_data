Препроцессинг под ImageNet: `Resize(224)` + `Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])`. **Честный прогон** (заморозка + только новая голова, подвыборка CIFAR 3000/1000, Adam lr=0.001, CPU): эпохи 0.758 / 0.802 / 0.818 — т.е. ~82% за 3 эпохи на малой выборке (наша CNN с нуля давала ~70% на всех 50k). На полном CIFAR+GPU+fine-tuning → 90%+. Иллюстрации (проверены curl, 200 image/png): Transfer_Learning.png и Resnet-18_architecture.svg (Wikimedia). Врезки GPU+автозагрузка добавлены.

> **Для 6.5:** аугментация через `transforms` (RandomHorizontalFlip/RandomCrop/RandomRotation/ColorJitter — все проверены, работают). Иллюстрация: Data_Augmentation_of_rock_images_revised.jpg (Wikimedia). Врезки GPU+автозагрузка добавлены (конвенция).

## 5. ПРАВИЛА СОЗДАНИЯ ФАЙЛОВ (КРИТИЧНО!)

### 5.1. theory.md — НЕ сухая теория, а РАССКАЗ

**Принципы:**

1. **Раздел 0 — главные термины урока** с врезками 🔵:
   ```markdown
   ### 🔵 Название термина
   Определение простыми словами. Аналогия из жизни. Пример.
   ```

2. **Раздел 1 — история / мотивация**. Начать с **рассказа** или **примера**, а не с формулы.
   - «Представь, что ты — учитель... к тебе приходит ученик и спрашивает...»
   - «Попробуй написать обычным программированием — сразу появляются проблемы...»

3. **Перед каждым кодом — "Что мы хотим сделать"**. Не сразу формула.

4. **После каждого кода — "Что это значит"**. Расшифровка чисел, не «вот результат».

5. **Реальные применения** (раздел в конце темы): «Это используют в банках, медицине, маркетинге...».

6. **Связь с предыдущими уроками**: «Помнишь Урок 1.7? Мы там делали то же самое...».

7. **Конкретные числа в примерах**: «$50 000 ошибки», «80% точности», «прирост +14%». Не «X», «Y».

**Пример хорошего стиля — см. `модули/03-классический-ml-основы/урок-03-линейная-регрессия/theory.md`** — это образец.

### 5.2. practice.md — пошаговый разбор с КОММЕНТАРИЯМИ

**Принципы:**

1. **В начале — "Что мы будем делать на уроке"** — постановка задачи человеческим языком, **с конкретными числами**.

2. **Каждое задание начинается с:**
   - **«Что мы хотим сделать»** — цель в одном-двух предложениях.
   - **«Что мы сделаем»** — список шагов словами.
   - **«Что у нас будет в итоге»** — ожидаемый результат.

3. **Каждый код-блок снабжён:**
   - **"Что мы делаем по шагам"** — что делает каждая строка.
   - **"Что произошло"** — что изменилось внутри (модель/данные).
   - **"Что это значит"** — расшифровка чисел в выводе.

4. **Расшифровка результатов** — не просто `# 0.97`, а:
   > «Точность 97% означает, что модель угадала 29 из 30 цветков...»

5. **"Магия" подчёркивается**: «Шесть строк кода — и модель работает на 100%!».

**Пример хорошего стиля — `модули/03-классический-ml-основы/урок-03-линейная-регрессия/practice.md`**.

### 5.3. homework.md — БЕЗ ГОТОВОГО КОДА, С ВОПРОСАМИ НА РАЗМЫШЛЕНИЕ

**Главное правило:** **подсказки не должны превращаться в готовый код для копирования**. Иначе дети просто копипастят и ничего не учат.

**Принципы:**

1. **В начале — шпаргалка** (минимум команд из урока), чтобы не было «не помню синтаксис».

2. **Подсказки — это НЕ готовый код**. Это:
   - Описание шагов словами («1. Создай... 2. Посчитай... 3. Сравни...»).
   - Сигнатуры функций (`def func(...)`) — пусть тело пишут сами.
   - Точечные подсказки: «используй `np.linalg.norm`», «фильтр через `if x % 3 == 0`».
   - **Иногда** шаблоны с пропусками `_____` — только для самых сложных конструкций.

3. **🤔 ВОПРОСЫ НА РАЗМЫШЛЕНИЕ после КАЖДОЙ задачи (это ОБЯЗАТЕЛЬНО):**
   - «Что произойдёт, если изменить X на Y?»
   - «Почему мы использовали Z, а не альтернативу?»
   - «Можно ли решить иначе?»
   - «Какой результат тебя удивил?»
   - **«Сначала предскажи, потом проверь»** — ключевой приём.
   - «Назови **3 примера из жизни**, где это работает».

4. **Финальная фраза в конце урока (всегда):**
   > **«Без ответов на вопросы — задача не считается решённой.»**
   > **«Главное — понять, а не просто прогнать код.»**

5. **Уровни сложности:**
   - **Уровень 1** — обязательная база.
   - **Уровень 2** — связки с прошлыми уроками.
   - **Уровень 3** — со звёздочкой (по желанию).

6. **Поддерживающий тон:** «Не пугайся!», «Это нормально», «Не расстраивайся».

**Пример хорошего стиля — `модули/03-классический-ml-основы/урок-03-линейная-регрессия/homework.md`**.

### 5.4. solutions.md — ПОЛНОЕ РЕШЕНИЕ ДЛЯ ПРЕПОДАВАТЕЛЯ

**Принципы:**

1. **Заголовок:** «НЕ выдавать ученикам».

2. **Для каждой задачи:**
   - **Полный эталонный код** с комментариями.
   - **Ожидаемый вывод** с конкретными числами.
   - **Подробный разбор** — что делает каждая строка, что значит результат.
   - **Ответы на ВСЕ вопросы размышления** ученика (развёрнутые!).
   - **«Что объяснить классу»** — педагогические замечания.
   - **«Типовые ошибки»** — с примерами «как выглядит» и как ловить.

3. **В конце файла:**
   - **«Главные ошибки»** — сводка.
   - **«Если у многих не получилось»** — что делать.
   - **«Если кто-то справился слишком быстро»** — **бонусные задачи** (3-5 штук).

- **pyttsx3 в Colab ОБЫЧНО НЕ РАБОТАЕТ** (нет аудиоустройства) → в Colab синтез речи через **gTTS**; pyttsx3 — только на своём ПК офлайн. Это явно писать в уроках.
- В Colab librosa/cv2/skimage/PIL уже стоят.

**Грабли по библиотекам (проверено на практике):**
- **transformers:** v5.x УБРАЛ pipeline-алиасы `question-answering` и `translation`! Использовать **v4.x** (в Colab обычно v4). `translation` требует `sentencepiece`.
- **CNN forward:** использовать `x.reshape(x.size(0),-1)`, НЕ `x.view(...)` (ошибка contiguity после conv/pool).
- **librosa.load** по умолчанию ресемплит к **22050 Гц** (для исходного sr — `sr=None`). Примеры: `librosa.ex('trumpet')` и т.п.
- **CountVectorizer/TfidfVectorizer** по умолчанию: нижний регистр, токены **от 2 букв** (1-буквенные слова «и/в/я» выбрасываются!), кириллица работает.
- **Wikimedia через urllib даёт 403** → грузить картинки для датасета через skimage или с заголовком `User-Agent`. Для проверки URL картинок в curl — тоже `-A "Mozilla/..."` (иначе бывает 429/403).
- **Whisper на синтетическом/роботном голосе (pyttsx3) распознаёт ПЛОХО** (обучен на живой речи) — на чистой человеческой речи отлично. Хороший честный разговор «качество входа→выхода».
- **GloVe/gensim:** модель английская → русские слова = `KeyError`. Среди `most_similar` бывают junk-токены (брать чистые примеры king/dog).
